# مقیاس: از ۷ میلیون تا ۷ تریلیون پارامتر — اعداد واقعی

تو پرسیدی «ترجیحاً تا ۷ تریلیون پارامتر برود». این سند صادقانه جواب می‌دهد: چه
چیزی روی سخت‌افزار تو ممکن است، چه چیزی نیست، و کد چه چیزی را پشتیبانی می‌کند.

اول از همه، خودت حساب کن:

```bash
slm plan --params 7e12 --experts 256 --topk 8 --ctx 8192 --ram 16 --vram 2
```

## ۱) ۷ تریلیون پارامتر یعنی چه؟

خروجی واقعی `slm plan` برای ۷T (شکل تخمینی ۳۲۹ لایه × ۴۲۱۰۹ بُعد):

```
weights
  fp32             : 25.47 TiB
  fp16/bf16        : 12.73 TiB
  int8 (group 64)  : 6.76 TiB
  int4 (group 64)  : 3.58 TiB

training state (bf16 weights, full)
  weights          : 12.73 TiB
  gradients        : 12.73 TiB
  AdamW fp32       : 50.93 TiB   (8-bit: 12.73 TiB)
  activations      : 2.48 TiB   (checkpointing: 219.09 GiB)
  total            : 38.41 TiB .. 78.87 TiB

verdict for your machine (--ram 16 GiB, --vram 2 GiB)
  train (min config) in RAM   : does NOT fit  (needs 38.41 TiB)
  int8 inference in RAM       : does NOT fit  (needs 6.76 TiB)
  accelerators of 80 GiB      : 489 for sharded training, 163 for fp16 inference

compute for a from-scratch run
  tokens (20x params): 1.4e+14
  training FLOPs     : 2.06e+27
  one accelerator at 4e+14 FLOP/s: 1.64e+05 GPU-years
  1000 accelerators  : 5.97e+04 days   (~۱۶۳ سال)
  this CPU backend (5.8e+10 FLOP/s): 1.13e+09 years
```

یعنی:

* **ذخیره‌سازی**: فقط وزن‌ها با int4 حدود **۳.۶ ترابایت** است. روی ۱۶GB RAM جا
  نمی‌شود؛ روی ۲GB VRAM حتی یک درصدش هم جا نمی‌شود.
* **آموزش**: حداقل ~**۳۸ ترابایت** حالت آموزش → حدود **۴۹۰ کارت ۸۰ گیگی**
  فقط برای جا شدن.
* **محاسبه**: با نسبت Chinchilla به ~۱.۴×۱۰¹⁴ توکن نیاز دارد؛ روی ۱۰۰۰ کارت
  رده‌ی H100 چیزی حدود **۱۶۰ سال** طول می‌کشد (هزینه‌ای در حد چند صد میلیارد دلار).
* برای مقایسه: بزرگ‌ترین مدل‌های باز امروزی (سبک DeepSeek-V3) حدود
  **۶۷۱ میلیارد** پارامتر کل با ~۳۷ میلیارد فعال‌اند — یعنی یک‌دهم عددی که گفتی،
  و آن هم روی هزاران کارت آموزش دیده است.

**نتیجه: ۷ تریلیون پارامتر با هیچ ترفند نرم‌افزاری روی ۱۶GB RAM / ۲GB VRAM
قابل آموزش یا حتی نگه‌داری نیست.** هر کسی خلافش را بگوید، یا مقیاس را اشتباه
گفته یا «پارامتر» را چیز دیگری تعریف کرده.

## ۲) پس چه کاری *می‌شود* کرد؟

### ۲.۱ نردبان واقعی روی سخت‌افزار تو

خروجی `slm plan --ram 16 --vram 2` در انتها:

```
what actually fits here
  full training      : up to ~2.86 B parameters (bf16 + 8-bit optimiser,
                       checkpointing, micro-batch 1)
  int8 inference     : up to ~16.17 B parameters
  partial fine-tune  : a 16.17 B model with 5% trainable
```

| هدف | روی ۱۶GB RAM (CPU) | روی ۲GB VRAM |
|---|---|---|
| آموزش کامل از صفر | تا ~۲.۸B پارامتر *جا می‌شود*، اما با این بکند CPU زمانش سال است. عملی: **≤ ۱۵۰M** | تا ~۱۵۰M با bf16 + 8-bit optimiser + checkpointing |
| ادامه‌ی آموزش / fine-tune جزئی | تا ~۳B با `last_k_blocks` | **~۱–۳B** با ۵٪ پارامتر trainable |
| inference (int8) | تا ~۱۶B | تا ~۱.۸B |
| این پروژه، امروز | ۷.۳M آموزش‌دیده و حاضر در `models/` | همان |

توصیه‌ی عملی برای «حرفه‌ای شدن» بدون تغییر سخت‌افزار: **۱۲۴M تا ۳۵۰M پارامتر**،
که با `configs/slm-124m.conf` و بکند libtorch روی یک GPU اجاره‌ای چند ساعته
آموزش‌پذیر است و کیفیتش برای فارسی/انگلیسی/پایتون واقعاً قابل استفاده است.

### ۲.۲ چه چیزهایی در همین کد برای مقیاس آماده است

| قابلیت | وضعیت | اثر روی مقیاس |
|---|---|---|
| RoPE (بدون جدول موقعیت) | ✅ پیاده | سقف طول متن در وزن‌ها حک نمی‌شود؛ context بعداً قابل افزایش است |
| GQA (`n_kv_head`) | ✅ پیاده | KV cache تا ۴-۸ برابر کوچک‌تر: تنها راه inference طولانی روی ۲GB |
| RMSNorm + SwiGLU | ✅ پیاده | همان معماری مدل‌های امروزی؛ کیفیت بیشتر به‌ازای هر پارامتر |
| gradient checkpointing | ✅ پیاده و اندازه‌گیری‌شده | ۴۳۲MiB → ۹۰MiB فعال‌سازی |
| freeze جزئی (`last_k_blocks`) | ✅ پیاده | حالت AdamW فقط برای بخش trainable ساخته می‌شود |
| ذخیره‌سازی fp16 / int8 گروهی | ✅ پیاده | چک‌پوینت ۲ و ~۴ برابر کوچک‌تر |
| بکند libtorch + CUDA | ✅ پیاده | ~۴ برابر روی CPU، و مسیر GPU |
| `slm plan` | ✅ پیاده | قبل از هر ران، جواب «جا می‌شود یا نه» |
| **MoE (mixture of experts)** | ❌ پیاده نشده (فقط در planner مدل‌سازی شده) | تنها راه رسیدن به تریلیون‌ها پارامتر: پارامتر کل زیاد، پارامتر *فعال* کم |
| **شاردینگ چند-دستگاهی (ZeRO/FSDP)** | ❌ پیاده نشده | لازمه‌ی هر چیزی بزرگ‌تر از یک دستگاه |
| **int8/int4 در مسیر محاسبه** | ❌ (فعلاً فقط ذخیره‌سازی) | inference مدل بزرگ روی VRAM کم |

### ۲.۳ اگر واقعاً بخواهی به مرزهای تریلیونی نزدیک شوی

مسیر درست همان است که DeepSeek/Qwen/Mixtral رفته‌اند:

1. **MoE با top-k routing**: مثلاً ۲۵۶ متخصص و top-8. پارامتر کل ۷T ولی
   **فعال به‌ازای هر توکن ~۲.۵T** (خروجی planner). این FLOPs را کم می‌کند، اما
   **حافظه را کم نمی‌کند** — همه‌ی متخصص‌ها باید جایی ذخیره شوند.
2. **شاردینگ**: tensor/pipeline/expert parallelism روی چند صد دستگاه + ZeRO-3
   برای حالت بهینه‌ساز.
3. **بهینه‌ساز کم‌حافظه**: 8-bit Adam یا Adafactor (در planner لحاظ شده).
4. **آموزش fp8/bf16 با master weight شارد‌شده**.
5. **خواندن جریانی وزن از دیسک (offload)**: برای *inference* می‌شود مدل را
   لایه‌به‌لایه از NVMe خواند؛ سرعت به پهنای‌باند دیسک می‌افتد (چند توکن بر ثانیه
   در بهترین حالت).

اگر مسیر MoE برایت مهم است، بگو تا آن را در همین موتور پیاده کنم: به یک عملگر
router + gather/scatter با backward نیاز دارد (حدود ۳۰۰ خط + gradcheck) و بعد
`slm plan --experts` از تخمین به واقعیت تبدیل می‌شود.

## ۲.۴ درس PicoLM: ۲ میلیارد پارامتر روی همین سیستم — اما فقط برای اجرا

پروژه‌ی [PicoLM](https://github.com/RightNow-AI/picolm) یک مدل ۱ میلیاردی را در
**۴۵MB RAM** روی یک برد ۱۰ دلاری اجرا می‌کند. چطور؟ سه ترفند، و هیچ‌کدام مربوط به
*آموزش* نیست:

1. **کوانتیزاسیون Q4_K** — هر وزن ~۴.۵ بیت (به‌جای ۳۲ بیت): ۱B پارامتر ≈ ۶۰۰MB.
2. **mmap کردن فایل وزن‌ها** — وزن‌ها هرگز کامل در RAM نمی‌نشینند؛ کرنل صفحه‌به‌صفحه
   می‌آورد. مصرف RAM ≈ اندازه‌ی فعال‌سازی‌ها، نه اندازه‌ی مدل.
3. **ضرب ماتریسی کوانتیزه** — dequant داخل کرنل، بدون بازکردن کل ماتریس.

پس پاسخ «۲ میلیارد پارامتر روی سیستم من»:

| کار | ۲B پارامتر روی ۱۶GB RAM / ۲GB VRAM |
|---|---|
| **اجرا (inference)** با Q4 + mmap | ✅ عملاً ممکن: ~۱.۲GB وزن، چند توکن بر ثانیه روی CPU |
| **fine-tune جزئی** (LoRA یا ۲ بلوک آخر) | ✅ ممکن: ~۱.۵–۲.۵GB با bf16 + 8-bit optimizer + checkpointing |
| **آموزش کامل از صفر** | ❌ ۲B × ۲۰ توکن = ۴۰ میلیارد توکن؛ روی این CPU ≈ **۴۰ سال**. روی ۸×A100 حدود ۲–۳ هفته |

در همین مخزن، مسیر ۱ و ۲ از قبل پشتیبانی می‌شوند مگر یک قطعه: **ضرب ماتریسی
int4/int8**. امروز کوانتیزاسیون در لایه‌ی ذخیره‌سازی است (`slm quantize --dtype q8`،
۳.۹ برابر کوچک‌تر با خطای RMS ۰.۰۲٪) و mmap برای *توکن‌ها* پیاده شده (`TokenStore`).
برای اجرای واقعی یک مدل ۲B روی ۲GB باید همان کاری را کرد که PicoLM کرده:
`Q4 + mmap + dequant داخل GEMM`. این کوچک‌ترین قطعه‌ی باقی‌مانده‌ی این پروژه است و
با معماری فعلی (`linear()` تک‌نقطه‌ی ورود همه‌ی ضرب‌ها) تمیز جا می‌شود.

## ۳) چرا «کوچک اما تخصصی» انتخاب بهتری است

با بودجه‌ی ثابت، مدل ۳۵۰M که فقط فارسی/انگلیسی/پایتون دیده، در همین سه دامنه از
مدل ۷B عمومی بهتر جواب می‌دهد و روی لپ‌تاپ تو **اجرا** می‌شود. کل معماری این پروژه
حول همین ایده ساخته شده:

* توکنایزر مخصوص همین سه دامنه (fertility فارسی ۴.۹ کاراکتر بر توکن)
* holdout و گیت جداگانه برای هر زبان
* سه مکانیزم خودآموزی که مدل را با *کاربر واقعی* تطبیق می‌دهند، به‌جای
  بزرگ‌کردن بی‌هدف
